Session 01

Cài đặt môi trường

Tài liệu học tập chuyên sâu. Trực quan hóa & Tương tác động.

1
Thách thức về tính nhất quán và cô lập môi trường trong doanh nghiệp
  • Thách thức về tính nhất quán môi trường toàn cục:
    • Trong môi trường sản xuất của doanh nghiệp công nghệ, các nhóm phát triển lớn làm việc đồng thời trên nhiều dự án phần mềm khác nhau trên cùng một máy tính.
    • Tình trạng này dẫn đến xung đột trầm trọng về phiên bản thư viện giữa các dự án khác biệt.
    • Hiện tượng này được gọi là Dependency Hell (Địa ngục phụ thuộc), xảy ra khi Dự án A yêu cầu phiên bản hệ thống cũ trong khi Dự án B bắt buộc phải sử dụng phiên bản mới nhất.
    • Cài đặt trực tiếp lên hệ điều hành gây ghi đè tệp tin toàn cục và làm hỏng luồng chạy của các ứng dụng cũ đang vận hành ổn định.
  • Lỗi đồng bộ mã nguồn giữa các hệ điều hành:
    • Sự bất đồng bộ về cấu hình đường dẫn và biến môi trường hệ thống xảy ra thường xuyên giữa Windows, macOS và Linux.
    • Code chạy thành công trên máy của lập trình viên này nhưng lại gặp lỗi nghiêm trọng khi triển khai trên máy chủ hoặc máy của thành viên khác.
    • Hệ thống thiếu linh hoạt trong việc tự động phát hiện và liên kết đúng trình thông dịch dẫn đến thời gian cấu hình thủ công kéo dài, làm giảm hiệu suất phát triển.
  • Tác động tiêu cực của cấu hình thủ công sai quy chuẩn:
    • Lập trình viên tự ý chỉnh sửa thủ công biến hệ thống chứa tệp chạy dẫn đến lỗi ghi đè khóa môi trường cục bộ.
    • Phần mềm hoạt động chập chờn, không thể tải đúng tài nguyên thư viện chuẩn khi khởi chạy trực tiếp thông qua cửa sổ dòng lệnh Terminal.
    • Các sai lệch về phiên bản gây ra các lỗi runtime âm thầm chỉ xuất hiện khi đưa mã nguồn lên môi trường kiểm thử thực tế.
2
Phân tích cơ chế cô lập môi trường ảo và so sánh hệ thống thực thi
  • Cơ chế cô lập môi trường của module venv:
    • Khi kích hoạt một virtual environment, hệ thống sẽ thực hiện chuyển hướng đường dẫn tìm kiếm thư viện mặc định.
    • Hệ thống sử dụng biến môi trường PATH của phiên làm việc dòng lệnh hiện tại để đẩy đường dẫn thư mục bin (macOS/Linux) hoặc Scripts (Windows) của môi trường ảo lên vị trí ưu tiên đầu tiên.
    • Tất cả các lệnh gọi trình thông dịch Python cũng như việc truy xuất các gói bổ sung thông qua công cụ quản lý gói pip sẽ bị giới hạn hoàn toàn trong phạm vi thư mục cục bộ của môi trường ảo đó.
    • File cấu hình pyvenv.cfg lưu trữ thông tin chỉ mục của môi trường gốc giúp ánh xạ các thư viện chuẩn mà không cần sao chép toàn bộ mã nguồn lõi của Python, tiết kiệm dung lượng ổ đĩa.
  • Cơ chế quản lý môi trường của Anaconda:
    • Anaconda sử dụng trình quản lý gói độc lập mang tên conda để xử lý không chỉ thư viện Python mà còn cả mã nguồn biên dịch của hệ thống như C/C++.
    • Anaconda tối ưu hóa việc phân tách bằng cách cung cấp các gói công cụ nhị phân đã biên dịch sẵn giúp tối ưu hiệu năng tính toán số học nâng cao.
    • Tuy nhiên, nhược điểm của giải pháp này là dung lượng cài đặt chiếm dụng tài nguyên đĩa cứng rất lớn, không phù hợp cho các dự án web nhẹ hoặc ứng dụng nhỏ gọn.
  • Bảng so sánh kỹ thuật môi trường thực thi của các ngôn ngữ:

3
Giải pháp thiết lập môi trường phát triển đúng quy chuẩn kỹ thuật
  • Quy trình cài đặt Python và tích hợp PATH:
    • Tải bộ cài đặt chính thức của Python phiên bản ổn định từ trang chủ python.org.
    • Thực hiện chạy bộ cài đặt và bắt buộc tích hợp tùy chọn Add Python to PATH để hệ thống tự động nhận diện lệnh chạy.
  • Qấu hình Visual Studio Code làm môi trường phát triển chính:
    • Cài đặt trình soạn thảo VS Code từ nguồn phân phối chính thức.
    • Tiến hành cài đặt tiện ích mở rộng Python extension cung cấp bởi Microsoft để kích hoạt các tính năng phân tích mã nguồn và tích hợp thiết bị dòng lệnh.
  • Tạo lập và kích hoạt môi trường ảo cho dự án mới:
    • Mở thư mục gốc của dự án trên ứng dụng dòng lệnh.
    • Khởi tạo môi trường ảo bằng lệnh sau: python -m venv app_env.
    • Kích hoạt phân vùng môi trường ảo cô lập:
      • Trên hệ điều hành Windows (PowerShell): Chạy script ./app_env/Scripts/Activate.ps1.
      • Trên hệ điều hành macOS/Linux: Chạy lệnh source app_env/bin/activate.
  • Liên kết môi trường ảo với trình soạn thảo VS Code:
    • Kích hoạt bảng điều khiển của VS Code bằng tổ hợp phím Ctrl + Shift + P (hoặc Cmd + Shift + P trên macOS).
    • Tìm kiếm lựa chọn cấu hình Python: Select Interpreter và chỉ định đường dẫn đến file thực thi Python nằm bên trong môi trường ảo app_env vừa thiết lập.

Phân tích kết quả vận hành và kịch bản thực thi thực tế
Nhấp vào để đóng/mở mã nguồn chi tiết
example.python 
import sys


def check_development_environment():
    # Lay duong dan thuc thi cua trinh thong dich
    interpreter_path = sys.executable
    active_prefix = sys.prefix
    base_prefix = getattr(sys, "base_prefix", sys.prefix)

    # Xac dinh trang thai co lap cua phan vung moi truong
    is_virtual_env = active_prefix != base_prefix

    print("=== ENVIRONMENT STATUS ===")
    print("Interpreter Path:")
    print(interpreter_path)
    print("Is Active Virtual Environment:")
    print(is_virtual_env)


if __name__ == "__main__":
    check_development_environment()
  • Quy trình nạp và phân tích cấu trúc hệ thống:
    • Khi file mã nguồn chạy trong môi trường ảo, chương trình truy cập biến hệ thống để đọc tiền tố thư mục hiện hành.
    • Bộ xử lý so sánh giá trị phân vùng thực tế của dự án với phân vùng của nhân hệ điều hành.
    • Nhờ cơ chế chuyển hướng thông tin, trình thông dịch liên kết chính xác thư viện cục bộ thay vì gây ảnh hưởng đến hệ thống máy chủ bên ngoài.
  • Console Output mong đợi khi chạy kiểm thử trong môi trường ảo thành công:

  True

Khảo thí & Đánh giá năng lực tự học
Câu 1: Hiện tượng Dependency Hell (Địa ngục phụ thuộc) xảy ra khi nào theo phản ánh từ thực tế doanh nghiệp?

Dependency Hell xảy ra khi các nhóm phát triển lớn làm việc đồng thời trên cùng một máy tính nhưng các dự án khác biệt lại yêu cầu các phiên bản thư viện hệ thống khác nhau (ví dụ Dự án A yêu cầu bản cũ, Dự án B yêu cầu bản mới nhất). Việc cài đặt trực tiếp lên hệ điều hành toàn cục gây ghi đè tệp tin và làm hỏng ứng dụng cũ.

Câu 2: Sự bất đồng bộ về hệ điều hành (Windows, macOS, Linux) ảnh hưởng như thế nào đến mã nguồn của dự án?

Sự bất đồng bộ này gây ra các lỗi về cấu hình đường dẫn và biến môi trường. Kết quả là mã nguồn chạy thành công trên máy của lập trình viên này nhưng lại gặp lỗi nghiêm trọng tại máy của thành viên khác hoặc trên máy chủ triển khai.

Câu 3: Việc lập trình viên tự ý chỉnh sửa thủ công biến hệ thống chứa tệp chạy dẫn đến hệ quả gì?

Dẫn đến lỗi ghi đè các khóa môi trường cục bộ, làm phần mềm hoạt động chập chờn, không thể tải đúng các tài nguyên thư viện chuẩn khi khởi chạy trực tiếp thông qua cửa sổ dòng lệnh Terminal, và tạo ra các lỗi runtime âm thầm chỉ xuất hiện trên môi trường kiểm thử thực tế.

LƯU Ý QUAN TRỌNG
  • Khái niệm môi trường ảo (venv): Giúp cô lập thư viện giữa các dự án để tránh hoàn toàn hiện tượng xung đột phiên bản phụ thuộc giữa các ứng dụng khác nhau.
  • Vai trò của biến PATH: Đăng ký đường dẫn file thực thi của Python vào biến PATH của hệ điều hành là điều kiện bắt buộc để có thể thực thi lệnh chạy từ bất kỳ thư mục nào trên dòng lệnh.
  • Lỗi thiếu gói thư viện: Lỗi runtime ModuleNotFoundError xảy ra do lập trình viên quên kích hoạt môi trường ảo cục bộ trước khi khởi chạy ứng dụng hoặc cài đặt gói thư viện sai phân vùng.
  • Lỗi không tìm thấy file: Lỗi runtime FileNotFoundError xuất hiện khi thư mục làm việc của terminal không trùng khớp với vị trí đặt tệp tin mã nguồn trong VS Code.
  • Lỗi quyền hạn thực thi: Lỗi runtime PermissionError xảy ra khi cố gắng cấu hình môi trường hoặc cài đặt gói hệ thống mà không khởi chạy terminal bằng quyền quản trị viên cao nhất.
