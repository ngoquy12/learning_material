Tổng quan nội dung & Lộ trình môn học

1. Tại sao cần nắm rõ Lộ trình và Chuẩn đầu ra môn học IT-105?

Trong môi trường phát triển phần mềm doanh nghiệp, việc lập trình viên bắt đầu dự án mà không nắm rõ mục tiêu, lộ trình kỹ thuật và quy trình quản lý nguồn mã nguồn sẽ dẫn đến nhiều rủi ro nghiêm trọng. Khi làm việc theo nhóm, nếu mỗi thành viên tự đặt tên nhánh, commit không theo chuẩn hoặc không nắm rõ mốc đánh giá sản phẩm, dự án dễ rơi vào tình trạng xung đột mã nguồn (merge conflicts), trễ tiến độ và sản phẩm đầu ra không đáp ứng yêu cầu kỹ thuật.

Môn học IT-105 được thiết kế nhằm trang bị cho sinh viên năng lực xây dựng giao diện Web responsive hiện đại kết hợp với framework JavaScript, đồng thời áp dụng quy trình quản lý dự án chuẩn doanh nghiệp ngay từ những buổi đầu tiên. Việc hiểu rõ chuẩn đầu ra CLO (Course Learning Outcomes) và PLO (Program Learning Outcomes) giúp sinh viên định hình rõ các cột mốc năng lực cần đạt được sau 10 buổi học.

Thách thức thực tế trong phát triển dự án nhóm:

  • Thiếu lộ trình rõ ràng dẫn đến việc phân bổ thời gian học tập và làm bài tập lớn không hợp lý.
  • Mã nguồn bị hỏng do không tuân thủ quy chuẩn phân nhánh Semantic Branching và quy trình Git Flow.
  • Lịch sử commit lộn xộn, không thể truy xuất nguồn gốc lỗi khi phát sinh sự cố trên nhánh chính.
  • Không nắm rõ trọng số đánh giá dẫn đến việc bỏ sót các điểm số thành phần quan trọng.

2. Tổng quan Lộ trình 10 buổi học, Chuẩn đầu ra và Quy chuẩn Git Enterprise

2.1. Mục tiêu môn học IT-105 và Lộ trình 10 buổi học

Môn học IT-105 được thiết kế nhằm cung cấp kiến thức toàn diện từ cơ bản đến nâng cao về lập trình Web Responsive và làm quen với các JS Framework hiện đại. Lộ trình được chia thành 10 buổi học có cấu trúc chặt chẽ.

  • Buổi 01: Tổng quan môn học, lộ trình, quy chế đánh giá và quy chuẩn Git Enterprise.
  • Buổi 02 - Buổi 04: Thiết kế giao diện Web Responsive với HTML5, CSS3, Flexbox, Grid System và Tailwind CSS.
  • Buổi 05 - Buổi 07: Lập trình JavaScript ES6+, xử lý bất đồng bộ (Async/Await, Promise) và làm việc với Web API.
  • Buổi 08 - Buổi 09: Xây dựng ứng dụng Web Single Page Application (SPA) với JavaScript Framework hiện đại.
  • Buổi 10: Tổng kết dự án, bảo vệ sản phẩm nhóm và làm bài thi thực hành cuối môn.

2.2. Chuẩn đầu ra môn học (CLO) và Chuẩn đầu ra chương trình (PLO)

Chuẩn đầu ra môn học quy định cụ thể các năng lực kiến thức, kỹ năng và thái độ mà sinh viên phải đạt được sau khi hoàn thành môn học.

  • CLO1: Sử dụng thành thạo Git CLI 2.45+ và GitHub Cloud để quản lý phiên bản mã nguồn theo mô hình Git Flow và Conventional Commits.
  • CLO2: Thiết kế và xây dựng giao diện Web tương thích đa thiết bị (Responsive Web Design) tuân thủ tiêu chuẩn UI/UX.
  • CLO3: Phát triển các tính năng tương tác người dùng phức tạp sử dụng JavaScript ES6+ và tích hợp RESTful APIs.
  • CLO4: Áp dụng tư duy làm việc nhóm, quản lý tiến độ công việc và bảo vệ sản phẩm phần mềm trước hội đồng đánh giá (đóng góp vào PLO3 và PLO5).

2.4. Quy chuẩn quản lý mã nguồn Enterprise với Git Flow và Conventional Commits

Trong suốt môn học, mọi bài tập và dự án phải tuân thủ nghiêm ngặt quy chuẩn đặt tên nhánh Semantic Branching và quy cách ghi log commit chuẩn mực.

Cấu trúc khai báo commit chuẩn Conventional Commits:

Cú pháp mẫu Git cli 2.45+, github cloud (conventional commits, git flow, semantic branching) 
<type>(<scope>): <short description>
  • type: Loại thay đổi mã nguồn (feat cho tính năng mới, fix cho sửa lỗi, docs cho tài liệu, style cho giao diện).
  • scope: Phạm vi mô-đun bị tác động (ví dụ: nav, auth, card).
  • short description: Mô tả ngắn gọn bằng tiếng Anh về nội dung thay đổi.

3.2. Quy chuẩn Đặt tên Nhánh theo Semantic Branching

Ví dụ minh họa cấu trúc đặt tên nhánh đúng quy chuẩn enterprise cho dự án web nhóm.

Mã nguồn minh họa Git cli 2.45+, github cloud (conventional commits, git flow, semantic branching) 
# Standard Semantic Branching Structure:
# main
-> Sole source of truth for release
# develop
-> Integration branch
# feature/- -> Short-lived feature branch

# Correct Branch Names:
feature/IT105-101-landing-page-hero
feature/IT105-102-cart-drawer-component
hotfix/IT105-999-fix-broken-flexbox-overflow

# Incorrect Branch Names (REJECTED in Code Review):
my-branch
test1
fix-bug
ha_code_responsive

3.3. Quy chuẩn Viết Commit Message chuẩn Conventional Commits

Mẫu các thông điệp commit đúng chuẩn để duy trì lịch sử Git sạch sẽ và hỗ trợ tự động hóa phát hành sản phẩm.

Mã nguồn minh họa Git cli 2.45+, github cloud (conventional commits, git flow, semantic branching) 
# Feature Addition:
feat(ui): add hamburger menu overlay for mobile viewports

# Bug Fixing:
fix(form): resolve layout shifting issue on input focus in iOS Safari

# Documentation Update:
docs(setup): document standard npm commands and git flow guidelines

# Code Refactoring:
refactor(scripts): modularize checkout logic into reusable ES6 modules

4. Tổng kết và các lưu ý

4.1. Các sai lầm phổ biến khiến sinh viên bị trừ điểm trong môn IT-105

  • Commit trực tiếp vào nhánh main hoặc master mà không thông qua nhánh feature và Pull Request.
  • Đặt thông điệp commit vô nghĩa như update, fix bug, done không tuân theo chuẩn Conventional Commits.
  • Nộp bài trễ deadline quy định trên hệ thống LMS hoặc nộp đường dẫn repository cá nhân bị khóa riêng tư (Private).
  • Không tham gia đủ 80% số buổi học dẫn đến việc bị cấm thi thực hành cuối môn.

4.2. Khuyến nghị thực hành tốt nhất (Best Practices)

  • Khởi tạo repository GitHub ở chế độ Public và cấu hình file .gitignore ngay từ Buổi 01.
  • Thực hiện commit nhỏ (atomic commits) thường xuyên thay vì dồn toàn bộ mã nguồn vào một commit lớn cuối ngày.
  • Theo dõi sát sao tiến độ làm bài tập Lab hàng tuần để tích lũy 20% điểm thành phần tối đa.
