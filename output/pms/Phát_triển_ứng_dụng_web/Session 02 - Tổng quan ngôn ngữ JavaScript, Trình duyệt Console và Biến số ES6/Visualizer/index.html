1. Tổng quan JavaScript và Cơ chế V8 Engine

Kiến trúc 2 Tầng V8 Engine: Ignition Interpreter & TurboFan Compiler

KIẾN TRÚC V8
  • Tầng 1 (Ignition Interpreter): Phân tích AST và chuyển đổi thành Bytecode để thực thi ngay lập tức mà không phải chờ đợi compile.
  • Tầng 2 (TurboFan JIT Compiler): Theo dõi các hàm được gọi lặp lại nhiều lần (Hot Functions), kết hợp Type Feedback để biên dịch thẳng thành Machine Code tối ưu tốc độ phần cứng cực đại.

Quy trình Thực thi: Source Code -> AST -> Bytecode -> Machine Code

QUY TRÌNH BIÊN DỊCH
1. Parser: JavaScript Text Code ➔ Abstract Syntax Tree (AST)
2. Ignition: AST ➔ Bytecode (Cold Execution)
3. Profiler: Thu thập Type Feedback trong Inline Cache (IC)
4. TurboFan: Bytecode + Type Feedback ➔ Highly Optimized Machine Code

Bẫy Deoptimization (Bailout): Khi Kiểu Dữ Liệu Bị Thay Đổi Bất Thường

BẪY HIỆU NĂNG

Cơ chế Deopt: Nếu TurboFan đã tối ưu một hàm với giả định tham số là số (Number), nhưng code bất ngờ truyền vào một chuỗi (String), V8 buộc phải Deoptimize (hủy Machine Code và quay về chạy Bytecode), làm tụt giảm hiệu năng tới 10-100 lần!

Senior Pro Tips: Viết Code Monomorphic Tối Ưu cho V8 Engine

PRO TRICK

Monomorphic Code: Luôn truyền cùng một kiểu dữ liệu và cấu trúc object cố định (cùng Hidden Class / Shape) vào hàm để V8 tối ưu hóa Inline Cache tối đa.

Node.js vs Browser: Node.js dùng V8 kết hợp với Libuv (C++) để xử lý Non-blocking I/O và Event Loop trên Server.

2. Cài đặt Môi trường VS Code Cursor và Node.js Runtime

Cơ chế Node.js Runtime (V8 + Libuv) vs Môi trường Trình duyệt

CƠ CHẾ RUNTIME
  • Node.js: Môi trường thực thi JavaScript ngoài trình duyệt, tích hợp V8 Engine của Google và thư viện Libuv (C++) để xử lý Non-blocking I/O và Event Loop.
  • Sự khác biệt cốt lõi: Node.js dùng để viết Backend API, truy cập hệ thống file (fs), database; còn Trình duyệt có DOM API (document, window) để tương tác giao diện.

Bảng Lệnh Terminal & CLI Quản lý Phiên bản Thiết yếu

BẢNG LỆNH CLI
Lệnh CLI Mục đích thực thi
node -v Kiểm tra phiên bản Node.js hiện tại (Khuyên dùng LTS)
node app.js Chạy trực tiếp file mã nguồn JavaScript qua terminal
npm -v Kiểm tra trình quản lý thư viện Node Package Manager

Bẫy Môi Trường: Gọi Window/DOM trong Node.js (ReferenceError)

LỖI THƯỜNG GẶP

Lỗi kinh điển: Gọi document.getElementById() hoặc alert() trong file chạy bằng node app.js sẽ ném lỗi ReferenceError: document is not defined vì Node.js không có giao diện DOM.

Ngược lại: Trình duyệt web không thể truy cập biến process.env hay thư viện fs (File System) do cơ chế bảo mật Sandbox.

3. Biến số ES6 (let, const, var) và Naming Convention

Bản chất Vùng nhớ RAM, Hoisting & Temporal Dead Zone (TDZ)

BẢN CHẤT BỘ NHỚ
  • Bộ nhớ Stack vs Heap: Kiểu nguyên thủy (Primitive: number, string, boolean) lưu trực tiếp trên Call Stack; Kiểu tham chiếu (Reference: Object, Array) lưu trên Memory Heap và con trỏ lưu trên Stack.
  • Hoisting & TDZ: var được đưa lên đầu phạm vi và gán undefined. Còn let và const cũng được hoisted nhưng nằm trong Temporal Dead Zone (TDZ) — truy cập trước khi khai báo sẽ ném lỗi ReferenceError.

Bảng So sánh Phạm vi: const vs let vs var

BẢNG SO SÁNH
Từ khóa Phạm vi (Scope) Gán lại (Reassign) Khai báo lại Hoisting
const Block Scope { } Không Không TDZ (Bảo vệ)
let Block Scope { } Có Không TDZ (Bảo vệ)
var Function / Global Có Có (Nguy hiểm) undefined

Bẫy Rò rỉ Biến với 'var' trong Vòng lặp & Naming Convention

BẪY THỰC TẾ

Bẫy rò rỉ: Dùng var i trong vòng lặp for làm biến i rò rỉ ra toàn bộ hàm hoặc window. Khi gọi callback/setTimeout, tất cả đều nhận giá trị cuối cùng của i.

Naming Convention chuẩn: Sử dụng camelCase cho biến (ví dụ: totalOrderAmount), UPPER_SNAKE_CASE cho hằng số cấu hình hệ thống (ví dụ: MAX_RETRY_COUNT).

Senior Pro Tips: Clean Code với Quy tắc Bất biến (Immutability)

BEST PRACTICE

Nguyên tắc vàng: Luôn khai báo const theo mặc định cho 95% biến số. Chỉ chuyển sang let khi biến đó bắt buộc phải thay đổi trong vòng lặp hoặc thuật toán.

Bảo vệ Object: const chỉ ngăn gán lại con trỏ, không ngăn sửa đổi thuộc tính con (mutation). Dùng Object.freeze(obj) khi cần bất biến tuyệt đối.

4. Nhập xuất dữ liệu Console và Chuỗi Template Literals

Cơ chế Xử lý Chuỗi & Nội suy Biểu thức (String Interpolation)

CƠ CHẾ THỰC THI
  • Template Literals (Backtick ` `): Cho phép chèn trực tiếp biểu thức JS qua cú pháp ${expression} mà không cần ngắt chuỗi và nối dấu +.
  • Hỗ trợ Multi-line String: Viết chuỗi nhiều dòng và định dạng HTML template trực tiếp mà không cần ký tự escape \n phức tạp.

Giải phẫu Cú pháp Backtick & Các Phương thức Console Chuyên nghiệp

CÚ PHÁP & CONSOLE API
console.table(userList); // In mảng/object dạng bảng trực quan
console.error(`Lỗi API: ${err.message}`); // In lỗi màu đỏ
console.time("RenderTimer"); ... console.timeEnd("RenderTimer");

Bẫy Nối Chuỗi Thủ Công (+) & Lỗi Format Dữ Liệu

LỖI THƯỜNG GẶP

Bẫy dấu cách & ép kiểu ngầm: Nối chuỗi bằng "Xin chào " + name + " bạn có " + count + 1 + " tin nhắn" sẽ in ra "bạn có 51 tin nhắn" do count + 1 bị coi là nối chuỗi.

Khắc phục: Sử dụng Template Literals `bạn có ${count + 1} tin nhắn` để biểu thức số học được tính toán chính xác trước khi đưa vào chuỗi.

Debug hiệu quả: Dùng console.log({ user, cart, total }) (bọc object) để console in ra kèm tên biến tự động!
