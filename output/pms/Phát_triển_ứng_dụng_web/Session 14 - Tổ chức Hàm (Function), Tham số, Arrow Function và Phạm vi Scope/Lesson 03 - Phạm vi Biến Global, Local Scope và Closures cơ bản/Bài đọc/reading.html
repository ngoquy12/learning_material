Trong các hệ thống thương mại điện tử quy mô lớn, việc xử lý tính toán đơn hàng, áp dụng mã giảm giá và tính toán doanh thu diễn ra liên tục với hàng nghìn giao dịch mỗi phút. Khi lập trình viên viết mã nguồn theo cách tuyến tính đơn giản, rủi ro lớn nhất thường xuất phát từ việc quản lý bộ nhớ và phạm vi truy cập của các biến trong chương trình JavaScript.

Hãy xét kịch bản một hệ thống bán hàng trực tuyến lưu giữ biến totalCartAmount ở phạm vi toàn cục (Global Scope). Khi hai người dùng thực hiện thanh toán đồng thời, hàm xử lý của người dùng A có thể vô tình ghi đè lên biến này trước khi người dùng B hoàn tất giao dịch. Kết quả là hóa đơn của người dùng B bị tính sai tiền, gây thất thoát tài chính và làm suy giảm uy tín của doanh nghiệp.

Hậu quả kỹ thuật & rủi ro vận hành:

  • Ô nhiễm phạm vi toàn cục (Global Scope Pollution): Biến khai báo không cẩn thận dễ bị ghi đè chéo bởi các mô-đun khác trong ứng dụng.
  • Lỗi Hoisting không kiểm soát: Gọi hàm hoặc biến trước khi định nghĩa có thể dẫn đến hành vi không xác định hoặc làm sập ứng dụng với lỗi Temporal Dead Zone (TDZ).
  • Rò rỉ dữ liệu riêng tư: Thông tin giỏ hàng và danh sách mã giảm giá của từng cá nhân không được đóng gói an toàn, dễ bị can thiệp trực tiếp từ console của trình duyệt.

Để giải quyết triệt để vấn đề này, JavaScript cung cấp các cơ chế mạnh mẽ bao gồm: phân định phạm vi biến toàn cục/cục bộ, cơ chế nâng biến (Hoisting) giúp tổ chức hàm mạch lạc, và đặc biệt là Closure giúp đóng gói dữ liệu riêng tư (Private State) hoàn hảo cho từng phiên làm việc của khách hàng.

2. Phạm vi biến, Cơ chế Hoisting và Kỹ thuật đóng gói trạng thái với Closure

2.1. Phạm vi Biến Global và Local Scope

Phạm vi của biến (Scope) xác định nơi mà biến đó có thể được truy cập và sử dụng trong mã nguồn. Trong JavaScript, phạm vi được chia thành các cấp độ chính:

  • Global Scope (Phạm vi Toàn cục): Biến được khai báo bên ngoài tất cả các hàm hoặc khối lệnh. Biến toàn cục có thể được truy cập và chỉnh sửa từ bất kỳ vị trí nào trong ứng dụng.
  • Function Scope (Phạm vi Hàm): Biến được khai báo bên trong một hàm chỉ có thể được sử dụng nội bộ trong hàm đó và sẽ giải phóng khỏi bộ nhớ khi hàm kết thúc.
  • Block Scope (Phạm vi Khối): Được giới hạn trong cặp dấu ngoặc nhọn {} (như trong lệnh if, for) khi sử dụng từ khóa let hoặc const.

Bài toán thực tế trong E-commerce:

Các cấu hình toàn hệ thống như tỷ giá quy đổi tiền tệ (DEFAULT_EXCHANGE_RATE) nên đặt ở Global Scope ở dạng hằng số const. Ngược lại, tính toán giá trị tạm thời của giỏ hàng phải đưa vào Local Scope của hàm để tránh truy cập trái phép từ bên ngoài.

// Biến Global cấu hình tỷ giá quy đổi tiền tệ
const DEFAULT_EXCHANGE_RATE = 25000;

function calculateVndPrice(usdAmount = 0) {
  // Biến Local chỉ truy cập được bên trong hàm này
  const totalVnd = usdAmount * DEFAULT_EXCHANGE_RATE;
  return totalVnd;
}

console.log(calculateVndPrice(10)); // Kết quả: 250000
// console.log(totalVnd); // Lỗi ReferenceError: totalVnd is not defined

2.2. Cơ chế Hoisting trong JavaScript
Hoisting là cơ chế mặc định của JavaScript trình biên dịch đưa phần khai báo của biến và hàm lên đầu phạm vi chứa nó (Global hoặc Function Scope) trước khi thực thi mã nguồn.
  • Function Declaration: Được hoisted hoàn toàn cả phần khai báo và định nghĩa. Do đó, bạn có thể gọi hàm ở dòng mã trước khi khai báo hàm đó.
  • Biến let và const (Temporal Dead Zone - TDZ): Phần khai báo vẫn được hoisted nhưng không được khởi tạo giá trị. Nếu truy cập biến trước dòng khai báo, trình duyệt sẽ ném ra lỗi ReferenceError do biến nằm trong vùng chết thời gian (TDZ).
  • Function Expression & Arrow Function: Khi gán hàm cho biến khai báo bằng let hoặc const, hàm tuân theo quy tắc hoisting của biến và không thể thực thi trước khi khai báo.
Lưu ý quan trọng về thiết kế mã nguồn:
Nên khai báo tất cả các biến bằng const hoặc let ở đầu khối lệnh và ưu tiên sử dụng Arrow Function hoặc Function Expression để kiểm soát luồng thực thi dự đoán được.

  

    

      
      
      
    

    
// Function Declaration: Được hoisting hoàn toàn (có thể gọi trước khi định nghĩa)
const discountedPrice = applyDefaultDiscount(100000);
console.log(discountedPrice); // Kết quả: 90000

function applyDefaultDiscount(price) {
  return price * 0.9;
}

// Arrow Function / Function Expression: Không thể gọi trước khi khai báo
// calculateTax(100000); // Lỗi ReferenceError: Cannot access 'calculateTax' before initialization
const calculateTax = (price, taxRate = 0.1) => price * taxRate;

2.3. Khái niệm Closure cơ bản
Closure là một tính năng đặc biệt trong JavaScript nơi một hàm con (inner function) có thể ghi nhớ và truy cập vào các biến thuộc phạm vi của hàm bao ngoài (outer scope), ngay cả khi hàm bao ngoài đó đã kết thúc thực thi và trả về kết quả.
  • Cơ chế Lexical Scoping: Hàm con giữ lại một liên kết bộ nhớ tới môi trường nơi nó được tạo ra.
  • Bảo mật trạng thái (Private State): Biến nội bộ của hàm ngoại không thể bị sửa đổi trực tiếp từ phạm vi bên ngoài, giúp bảo vệ dữ liệu giỏ hàng an toàn khỏi các tác động ngoài ý muốn.
  • Khả năng tái sử dụng: Mỗi lần hàm ngoại được thực thi sẽ tạo ra một vùng không gian Closure độc lập hoàn toàn.
Ứng dụng doanh nghiệp:
Closure được sử dụng rộng rãi để tạo các bộ đếm giỏ hàng, trình quản lý phiên đăng nhập và các mô-đun lưu trữ trạng thái isolated cho từng người dùng riêng biệt.

  

    

      
      
      
    

    
function createCartCounter() {
  // Biến nội bộ được đóng gói (private state)
  let itemCount = 0;

  return function() {
    itemCount += 1;
    return itemCount;
  };
}

const addItem = createCartCounter();
console.log(addItem()); // Kết quả: 1
console.log(addItem()); // Kết quả: 2

3.1. Ví dụ 3.1: Tính tổng giỏ hàng với Phạm vi Biến Global và Local Scope
Yêu cầu nghiệp vụ: Xây dựng hàm calculateCartTotal nhận vào giá một sản phẩm và số lượng mua, áp dụng biến global thuế GTGT (VAT_RATE) và biến local để tính tổng tiền thanh toán.

  

    

      
      
      
    

    
// Biến Global cấu hình thuế GTGT cố định toàn hệ thống
const VAT_RATE = 0.1;

// Arrow function tính tổng tiền giỏ hàng với tham số mặc định
const calculateCartTotal = (pricePerItem, quantity = 1) => {
  // Biến local scope tính tổng tiền sản phẩm trước thuế
  const subtotal = pricePerItem * quantity;
  
  // Biến local scope tính số tiền thuế
  const taxAmount = subtotal * VAT_RATE;
  
  // Trả về tổng số tiền cần thanh toán
  return subtotal + taxAmount;
};

// Chạy thử nghiệm hàm
const itemPrice = 200000;
const itemQuantity = 3;

const finalPrice = calculateCartTotal(itemPrice, itemQuantity);
console.log("[INFO] Tổng tiền thanh toán đơn hàng:", finalPrice);
// Output: 660000

3.2. Ví dụ 3.2: Áp dụng Hoisting và Block Scope cho nghiệp vụ Mã giảm giá
Yêu cầu nghiệp vụ: Nâng cấp hệ thống với hàm kiểm tra mã giảm giá (dùng Function Declaration để tận dụng Hoisting) và tính hóa đơn cuối cùng (dùng Function Expression). Sử dụng block scope trong cấu trúc điều kiện để giới hạn mức giảm giá tối đa.

  

    

      
      
      
    

    
// Biến Global cấu hình phí giao hàng mặc định
const DEFAULT_SHIPPING_FEE = 30000;

// Function Expression chính tính hóa đơn cuối cùng
const calculateFinalInvoice = (itemPrice, quantity = 1, couponCode = "") => {
  const subtotal = itemPrice * quantity;
  
  // Gọi hàm applyCouponDiscount trước khi định nghĩa (dựa vào Hoisting)
  const discount = applyCouponDiscount(subtotal, couponCode);
  const totalAfterDiscount = subtotal - discount;
  
  return totalAfterDiscount + DEFAULT_SHIPPING_FEE;
};

// Function Declaration: Hoisted lên đầu scope nên có thể gọi ở dòng phía trên
function applyCouponDiscount(subtotal, couponCode = "") {
  let discountAmount = 0;
  
  // Block scope xử lý điều kiện giảm giá
  if (couponCode === "SALE10") {
    const discountRate = 0.1; // Chỉ tồn tại trong khối if này
    discountAmount = subtotal * discountRate;
    
    // Giới hạn giảm tối đa 50.000 VNĐ trong block scope nội bộ
    if (discountAmount > 50000) {
      discountAmount = 50000;
    }
  }
  
  return discountAmount;
}

// Chạy thử nghiệm nghiệp vụ
const totalOrder = calculateFinalInvoice(300000, 2, "SALE10");
console.log("[INFO] Tổng tiền hóa đơn sau giảm giá và phí ship:", totalOrder);
// Output: 580000 (Tạm tính 600k -> Giảm 50k max -> Cộng 30k ship)

4.1. Kiến thức trọng tâm
  • Biến Global nên hạn chế tối đa việc sử dụng và chỉ dành cho các hằng số cấu hình toàn ứng dụng.
  • Biến khai báo bằng let và const có thuộc tính Block Scope, giúp ngăn ngừa lỗi rò rỉ biến ngoài vòng lặp hoặc khối lệnh điều kiện.
  • Function Declaration được hoisted toàn bộ, trong khi Function Expression và Arrow Function tuân theo Temporal Dead Zone (TDZ).
  • Closure giúp đóng gói dữ liệu riêng tư (Private State), ngăn chặn sự can thiệp dữ liệu trái phép từ môi trường ngoài.

4.3. Các lỗi thường gặp & Lưu ý thực tế
Dưới đây là các lỗi lập trình phổ biến liên quan đến Scope và Closure cùng cách khắc phục theo tiêu chuẩn mã nguồn sạch:
Lỗi 1: Ghi đè biến Global vô tình do thiếu từ khóa khai báo

  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
function processPayment(amount) {
  // Quên dùng const/let -> vô tình tạo biến Global taxFee
  taxFee = amount * 0.1;
  return amount + taxFee;
}

processPayment(100000);
console.log(taxFee); // Output: 10000 (Làm ô nhiễm Global scope)



  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
function processPayment(amount) {
  // Luôn khai báo biến cục bộ với const hoặc let
  const taxFee = amount * 0.1;
  return amount + taxFee;
}

processPayment(100000);
// console.log(taxFee); // Lỗi ReferenceError đúng như kỳ vọng

Lỗi 3: Dùng chung biến State ngoài Closure gây sai lệch dữ liệu

  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// Biến state dùng chung ở môi trường Global
let sharedCartTotal = 0;

function createCartUpdater() {
  return function(price) {
    sharedCartTotal += price;
    return sharedCartTotal;
  };
}

const user1Cart = createCartUpdater();
const user2Cart = createCartUpdater();

user1Cart(100);
console.log(user2Cart(50)); // Mong muốn: 50, Thực tế: 150 (bị cộng dồn chung)

function createCartUpdater() {
  // Đưa biến vào bên trong Outer Function để tạo Closure riêng cho từng instance
  let personalCartTotal = 0;
  
  return function(price) {
    personalCartTotal += price;
    return personalCartTotal;
  };
}
