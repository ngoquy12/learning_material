Cú pháp Arrow Function ES6 và Tham số Mặc định

1. Vấn đề rủi ro dữ liệu rỗng và cú pháp cồng kềnh trong hệ thống tính hóa đơn E-commerce

Trong các hệ thống thương mại điện tử (E-commerce), thao tác tính toán giá trị hóa đơn là một trong những nghiệp vụ xuất hiện với tần suất cao nhất. Mỗi khi người dùng thêm sản phẩm vào giỏ hàng, áp dụng mã giảm giá hoặc chọn phương thức vận chuyển, hệ thống phải liên tục gọi các hàm tính toán để cập nhật lại tổng số tiền thanh toán.

Khi viết chương trình theo phong cách hàm truyền thống (Function Expression hoặc Function Declaration), cú pháp thường bị kéo dài bởi các từ khóa không cần thiết. Đồng thời, một rủi ro kỹ thuật lớn xảy ra khi người dùng không nhập mã giảm giá hoặc hệ thống không nhận được tham số phí vận chuyển từ phía giao diện. Khi đó, tham số truyền vào hàm sẽ nhận giá trị undefined. Thực hiện phép toán cộng trừ với undefined sẽ trả về kết quả NaN (Not a Number), khiến giao diện thanh toán hiển thị lỗi và ngưng trệ toàn bộ luồng mua hàng.

Rủi ro khi thiếu cơ chế bảo vệ tham số: Phép tính 150000 + undefined sẽ trả về NaN. Điều này phá hỏng cấu trúc dữ liệu hóa đơn và làm gián đoạn trải nghiệm người dùng.

Để giải quyết triệt để hai vấn đề trên, phiên bản ES6 đã giới thiệu hai tính năng quan trọng: Arrow Function giúp cô đọng tối đa cú pháp khai báo hàm, và Tham số Mặc định (Default Parameters) giúp thiết lập sẵn giá trị an toàn cho các tham số khi bị thiếu đối số truyền vào.

2. Cú pháp Arrow Function ES6 và Cơ chế Tham số Mặc định (Default Parameters)

2.1. Cú pháp Arrow Function ES6 và cơ chế Implicit Return

Vấn đề cú pháp truyền thống: Khai báo hàm biểu thức (Function Expression) truyền thống đòi hỏi các từ khóa dài dòng như function và lệnh return bắt buộc ngay cả khi thân hàm chỉ chứa duy nhất một phép tính.

Arrow Function giới thiệu ký hiệu mũi tên béo => để kết nối giữa danh sách tham số và thân hàm. Khi biểu thức trong thân hàm chỉ có một dòng duy nhất, ta có thể áp dụng cơ chế Implicit Return (ngầm định trả về) bằng cách loại bỏ cặp ngoặc nhọn {} và từ khóa return.

  • Cú pháp đầy đủ (Block Body): Sử dụng cặp ngoặc nhọn {} và bắt buộc phải có từ khóa return nếu muốn trả về giá trị.
  • Cú pháp ngắn gọn (Concise Body): Bỏ cặp ngoặc nhọn {} và từ khóa return, kết quả của biểu thức sau mũi tên sẽ tự động được trả về.
// 1. Function Expression truyền thống
const calculateSubtotalTraditional = function(price, quantity) {
    return price * quantity;
};

// 2. Arrow Function đầy đủ khối lệnh (Block Body)
const calculateSubtotalFull = (price, quantity) => {
    return price * quantity;
};

// 3. Arrow Function viết gọn (Implicit Return)
const calculateSubtotalShort = (price, quantity) => price * quantity;

2.2. Cơ chế Tham số Mặc định (Default Parameters)
Vấn đề dữ liệu rỗng: Trước ES6, để gán giá trị mặc định cho một tham số bị thiếu, các lập trình viên phải viết các câu lệnh kiểm tra thủ công như shippingFee = shippingFee || 30000;. Cách làm này dễ gây lỗi nếu đối số hợp lệ truyền vào là số 0 (vì 0 bị coi là falsy).
Tính năng Default Parameters trong ES6 cho phép gán trực tiếp giá trị mặc định ngay tại phần khai báo tham số của hàm với cú pháp param = defaultValue.
  • Điều kiện kích hoạt: Giá trị mặc định CHỈ được áp dụng khi đối số truyền vào tại vị trí tương ứng bị bỏ trống (không truyền) hoặc mang giá trị chính xác là undefined.
  • Cơ chế ghi đè: Nếu một giá trị hợp lệ (kể cả số 0, chuỗi rỗng "", hoặc false) được truyền vào, giá trị đó sẽ ghi đè lên giá trị mặc định.

  

    

      
      
      
    

    
// Khai báo giá trị mặc định cho phí giao hàng và giảm giá
const calculateTotal = (subtotal, shippingFee = 30000, discount = 0) => {
    return subtotal + shippingFee - discount;
};

// Trường hợp 1: Không truyền shippingFee và discount -> Tự động dùng 30000 và 0
console.log(calculateTotal(150000)); // 180000

// Trường hợp 2: Truyền đầy đủ đối số -> Ghi đè giá trị mặc định
console.log(calculateTotal(150000, 15000, 20000)); // 145000

2.3. Kết hợp Arrow Function và Tham số Mặc định trong xử lý nghiệp vụ
Quy tắc thiết kế hàm sạch: Các tham số bắt buộc phải truyền (required parameters) luôn luôn được đặt ở đầu danh sách tham số, theo sau bởi các tham số tùy chọn có giá trị mặc định (optional parameters).
Việc kết hợp Arrow Function với Tham số Mặc định giúp đoạn mã nghiệp vụ vừa đảm bảo tính cô đọng, vừa xây dựng được hàng rào phòng thủ dữ liệu vững chắc. Hàm sẽ xử lý linh hoạt từ các trường hợp gọi hàm đơn giản nhất cho đến các kịch bản tùy biến chuyên sâu mà không bị phát sinh lỗi runtime.

            3. Các ví dụ ứng dụng thực tiễn
          


          

            
3.1. Ví dụ 3.1: Tính tiền sản phẩm với số lượng mặc định
Xây dựng hàm Arrow Function ngắn gọn calculateItemTotal tính thành tiền cho một mặt hàng. Hàm nhận vào giá sản phẩm price và số lượng quantity. Nếu khách hàng không chọn số lượng, mặc định số lượng mua là 1.

  

    

      
      
      
    

    
// Ví dụ 3.1: Sử dụng Arrow Function ngắn gọn và Default Parameter
const calculateItemTotal = (price, quantity = 1) => price * quantity;

// Kiểm tra trường hợp khách hàng mua 1 sản phẩm (không truyền số lượng)
const totalSingle = calculateItemTotal(250000);
console.log("Tiền mua 1 sản phẩm mặc định:", totalSingle); // 250000

// Kiểm tra trường hợp khách hàng mua 4 sản phẩm
const totalMultiple = calculateItemTotal(250000, 4);
console.log("Tiền mua 4 sản phẩm:", totalMultiple); // 1000000

3.2. Ví dụ 3.2: Tính tổng hóa đơn có phí vận chuyển và giảm giá
Nâng cấp bài toán tính hóa đơn. Tạo hàm calculateInvoiceTotal nhận vào tổng tiền hàng subtotal, phí vận chuyển shippingFee (mặc định 30000 VNĐ) và số tiền giảm giá discountAmount (mặc định 0 VNĐ). Trả về tổng tiền phải thanh toán.

  

    

      
      
      
    

    
// Ví dụ 3.2: Nâng cấp nghiệp vụ hóa đơn đơn hàng
const calculateInvoiceTotal = (subtotal, shippingFee = 30000, discountAmount = 0) => {
    const finalTotal = subtotal + shippingFee - discountAmount;
    return finalTotal;
};

// Trường hợp 1: Đơn hàng tiêu chuẩn (dùng phí giao hàng mặc định 30000, không giảm giá)
const invoice1 = calculateInvoiceTotal(500000);
console.log("Tổng hóa đơn 1 (tiêu chuẩn):", invoice1); // 530000

// Trường hợp 2: Đơn hàng có ưu đãi phí giao hàng (15000) và mã giảm giá (50000)
const invoice2 = calculateInvoiceTotal(500000, 15000, 50000);
console.log("Tổng hóa đơn 2 (có khuyến mãi):", invoice2); // 465000

3.3. Ví dụ 3.3: Xử lý tóm tắt đơn hàng hoàn chỉnh cấp doanh nghiệp
Viết hàm formatOrderSummary xử lý tóm tắt đơn hàng E-commerce bao gồm: tên sản phẩm, đơn giá, số lượng (mặc định 1), tỷ lệ thuế VAT (mặc định 0.1 tương đương 10%), và phí giao hàng (mặc định 30000 VNĐ). Trả về một chuỗi định dạng thông báo hóa đơn chi tiết.

  

    

      
      
      
    

    
// Ví dụ 3.3: Hàm tóm tắt hóa đơn chuyên nghiệp xử lý đa tham số mặc định
const formatOrderSummary = (
    productName,
    unitPrice,
    quantity = 1,
    vatRate = 0.1,
    shippingFee = 30000
) => {
    const subtotal = unitPrice * quantity;
    const vatAmount = subtotal * vatRate;
    const grandTotal = subtotal + vatAmount + shippingFee;

    return `[HOÁ ĐƠN] Sản phẩm: ${productName} | Số lượng: ${quantity} | Tạm tính: ${subtotal} VNĐ | VAT (${vatRate * 100}%): ${vatAmount} VNĐ | Phí ship: ${shippingFee} VNĐ | Tổng thanh toán: ${grandTotal} VNĐ`;
};

// Khách hàng mua đơn giản: chỉ truyền tên sản phẩm và đơn giá
const summary1 = formatOrderSummary("Chuột không dây Logitech", 400000);
console.log(summary1);

// Khách hàng mua số lượng lớn: 3 chiếc, được miễn phí vận chuyển (shippingFee = 0)
const summary2 = formatOrderSummary("Màn hình Gaming 24 inch", 3500000, 3, 0.1, 0);
console.log(summary2);

            4. Tổng kết bài học & Các lỗi thường gặp
          


          

            
4.1. Kiến thức trọng tâm
  • Arrow Function sử dụng cú pháp ký hiệu mũi tên => giúp mã nguồn ngắn gọn hơn.
  • Cơ chế Implicit Return xảy ra khi loại bỏ cặp ngoặc nhọn {}, tự động trả về giá trị của biểu thức duy nhất.
  • Tham số mặc định (Default Parameters) gán giá trị phòng thủ khi đối số truyền vào là undefined hoặc không truyền đối số.
  • Các tham số mặc định nên luôn được đặt ở phía cuối danh sách tham số của hàm.
4.2. Bảng Ma trận Quyết định


Phương phápCú phápTính năng nổi bậtTrường hợp áp dụng
Function Expressionconst fn = function(a) { return a; }Rõ ràng, truyền thốngMã nguồn cũ (Legacy Code)
Arrow Function (Block Body)const fn = (a) => { return a; }Thân hàm nhiều dòng lệnhXử lý logic phức tạp có khai báo biến trung gian
Arrow Function (Implicit Return)const fn = (a) => aCực kỳ ngắn gọn, tự trả về giá trịTính toán đơn dòng, hàm biến đổi dữ liệu

4.3. Các lỗi thường gặp & Lưu ý thực tế
Lỗi 1: Quên từ khóa return khi dùng cặp ngoặc nhọn trong Arrow Function
Khi mở cặp ngoặc nhọn {} trong Arrow Function, hàm sẽ chuyển sang chế độ Block Body và không tự động trả về giá trị. Quên từ khóa return làm kết quả trả về luôn bị undefined.

  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// [LỖI] Dùng cặp ngoặc nhọn nhưng quên từ khóa return
const calculateDiscount = (price, discountRate = 0.05) => {
    price * discountRate;
};

const result = calculateDiscount(200000);
console.log("Số tiền giảm:", result); // Result: undefined



  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// [SỬA LỖI] Cách 1: Thêm từ khóa return đầy đủ
const calculateDiscountCorrect1 = (price, discountRate = 0.05) => {
    return price * discountRate;
};

// [SỬA LỖI] Cách 2: Bỏ cặp ngoặc nhọn để dùng Implicit Return
const calculateDiscountCorrect2 = (price, discountRate = 0.05) => price * discountRate;

console.log("Số tiền giảm 1:", calculateDiscountCorrect1(200000)); // 10000
console.log("Số tiền giảm 2:", calculateDiscountCorrect2(200000)); // 10000


Lỗi 2: Truyền giá trị null khiến tham số mặc định không được áp dụng
Tham số mặc định trong ES6 chỉ được kích hoạt khi đối số truyền vào là undefined hoặc không truyền. Nếu người dùng truyền giá trị null, JavaScript coi null là một giá trị xác định nên tham số mặc định sẽ KHÔNG được sử dụng.

  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// [LỖI] Truyền null khiến phí vận chuyển mặc định 30000 không được áp dụng
const calculateTotalWithShipping = (price, shippingFee = 30000) => price + shippingFee;

// Người dùng truyền null làm phí ship
const badTotal = calculateTotalWithShipping(100000, null);
// null bị ép kiểu thành 0 trong phép cộng -> Kết quả sai nghiệp vụ hệ thống
console.log("Tổng tiền lỗi:", badTotal); // 100000 (Thay vì 130000)



  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// [SỬA LỖI] Truyền undefined hoặc bỏ trống đối số để kích hoạt tham số mặc định
const calculateTotalWithShipping = (price, shippingFee = 30000) => price + shippingFee;

const correctTotal1 = calculateTotalWithShipping(100000, undefined);
const correctTotal2 = calculateTotalWithShipping(100000);

console.log("Tổng tiền đúng 1:", correctTotal1); // 130000
console.log("Tổng tiền đúng 2:", correctTotal2); // 130000
