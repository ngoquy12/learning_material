Khai báo Hàm (Function Declaration & Expression)

1. Tại sao cần đóng gói mã nguồn thành Hàm trong Hệ thống Tính toán Hóa đơn?

Trong hệ thống thu ngân của chuỗi siêu thị Rikkei Mart, hàng nghìn giao dịch diễn ra liên tục mỗi giờ. Mỗi hóa đơn thanh toán đòi hỏi nhiều bước tính toán nối tiếp nhau: tính thành tiền cho từng mặt hàng dựa trên đơn giá và số lượng, tính tổng tiền hàng, áp dụng tỷ lệ chiết khấu khuyến mãi, và đưa ra số tiền thực tế khách hàng phải trả.

Nếu viết toàn bộ chương trình theo dạng câu lệnh tuyến tính nối tiếp từ trên xuống dưới mà không có sự đóng gói mã nguồn, lập trình viên sẽ phải viết đi viết lại cùng một công thức nhân đơn giá với số lượng cho từng sản phẩm. Khi hệ thống xử lý đến mặt hàng thứ 100, tập tin mã nguồn sẽ bị phình to ra hàng ngàn dòng trùng lặp. Điều này dẫn đến những rủi ro kỹ thuật nghiêm trọng trong môi trường doanh nghiệp:

  • Nguy cơ sai sót dữ liệu cực cao: Việc chép lại công thức toán học ở hàng trăm vị trí khác nhau khiến chỉ cần một sơ suất gõ sai biến cũng sẽ dẫn đến tính sai tiền của khách hàng.
  • Phí tổn bảo trì khổng lồ: Khi siêu thị thay đổi chính sách giảm giá hoặc quy tắc tính thuế, đội ngũ kỹ sư phải tìm kiếm và chỉnh sửa thủ công ở tất cả các vị trí trong mã nguồn.
  • Không thể tái sử dụng: Khối mã tính toán tại quầy thu ngân không thể tái sử dụng cho ứng dụng di động hoặc website bán hàng trực tuyến của siêu thị.

Để giải quyết triệt để vấn đề này, ngôn ngữ JavaScript cung cấp khái niệm Hàm (Function). Hàm cho phép đóng gói một khối lệnh thực hiện công việc cụ thể thành một đơn vị mã duy nhất, nhận tham số đầu vào và trả về kết quả tính toán chính xác bất kỳ lúc nào được gọi.

2. Cú pháp và Cơ chế hoạt động của Function Declaration và Function Expression

2.1. Khai báo hàm dạng định danh (Function Declaration)

Function Declaration là phương pháp khai báo hàm truyền thống và phổ biến nhất trong JavaScript. Bạn sử dụng từ khóa function, theo sau là tên định danh của hàm, danh sách các tham số nằm trong cặp dấu ngoặc đơn (...), và khối mã thực thi nằm bên trong cặp dấu ngoặc nhọn {...}.

Cơ chế Hoisting (Đưa lên đầu phạm vi): Các hàm khai báo dạng Function Declaration được trình biên dịch JavaScript tự động di chuyển phần định nghĩa lên đầu phạm vi thực thi trước khi mã chạy. Do đó, bạn có thể thực thi (gọi) hàm tại các dòng mã nằm phía trên vị trí hàm được khai báo mà không gặp lỗi.

Cú pháp cơ bản của Function Declaration trong ngữ cảnh siêu thị:

// Gọi hàm trước khi khai báo (Vẫn hoạt động bình thường nhờ Hoisting) 
const totalAmount = calculateSubtotal(50000, 3);
console.log("Tổng tiền hàng:", totalAmount); // Kết quả: 150000

// Khai báo hàm dạng Function Declaration
function calculateSubtotal(price, quantity) {
  return price * quantity;
}

2.2. Khai báo hàm dạng biểu thức (Function Expression)
Function Expression là kỹ thuật định nghĩa một hàm (thường là hàm ẩn danh - anonymous function) và gán hàm đó trực tiếp vào một biến thông qua từ khóa const hoặc let. Hàm biểu thức được xử lý khi luồng thực thi chạy tới đúng dòng mã chứa phép gán đó.
Lưu ý về Hoisting với Function Expression: Khác với Function Declaration, biến chứa Function Expression chỉ được khởi tạo khi dòng mã chạy đến. Việc gọi hàm biểu thức trước khi khai báo sẽ lập tức gây ra lỗi nghiêm trọng ReferenceError: Cannot access 'calculateDiscount' before initialization.
Cú pháp tiêu chuẩn của Function Expression:

  

    

      
      
      
    

    
// Khai báo biến chứa hàm biểu thức
const calculateDiscount = function(subtotal, discountRate) {
  return subtotal * discountRate;
};

// Gọi hàm biểu thức sau khi đã khai báo
const discountValue = calculateDiscount(150000, 0.1);
console.log("Số tiền được giảm:", discountValue); // Kết quả: 15000

2.3. Tham số (Parameters) và Câu lệnh return
Để một hàm hoạt động linh hoạt với các dữ liệu đầu vào khác nhau, chúng ta sử dụng Tham số (Parameters) và nhận kết quả đầu ra thông qua từ khóa return.
  • Tham số (Parameters): Là các biến đóng vai trò giữ chỗ được niêm yết trong cặp dấu ngoặc đơn khi định nghĩa hàm (ví dụ: subtotal, discountAmount).
  • Đối số (Arguments): Là những giá trị dữ liệu cụ thể được truyền vào hàm khi tiến hành gọi hàm (ví dụ: 150000, 15000).
  • Từ khóa return: Ngừng ngay lập tức quá trình thực thi bên trong thân hàm và gửi giá trị kết quả trả về cho nơi gọi hàm. Nếu một hàm không có từ khóa return, kết quả thu được mặc định sẽ luôn là undefined.
Nguyên tắc Đơn nhiệm (Single Responsibility): Mỗi hàm chỉ nên đảm nhận một nhiệm vụ duy nhất. Việc tách biệt hàm tính số tiền giảm giá và hàm tính số tiền phải trả giúp mã nguồn siêu thị dễ kiểm thử và bảo trì.

  

    

      
      
      
    

    
function calculateFinalTotal(subtotal, discountAmount) {
  const finalTotal = subtotal - discountAmount;
  return finalTotal; // Trả về số tiền khách phải trả
}

const paymentAmount = calculateFinalTotal(150000, 15000);
console.log("Số tiền cần thanh toán:", paymentAmount); // Kết quả: 135000

            3. Các ví dụ ứng dụng thực tiễn
          


          

            
3.1. Ví dụ 3.1: Khai báo hàm tính tổng tiền một sản phẩm (Function Declaration)
Sử dụng cú pháp Function Declaration để định nghĩa hàm calculateItemTotal nhận vào hai tham số là đơn giá và số lượng, sau đó trả về tổng số tiền của sản phẩm đó.

  

    

      
      
      
    

    
// Khai báo hàm tính tiền mặt hàng (Function Declaration)
function calculateItemTotal(price, quantity) {
  const total = price * quantity;
  return total;
}

// Gọi hàm thực thi với sản phẩm giá 25.000 VNĐ, số lượng 4
const itemTotal = calculateItemTotal(25000, 4);
console.log("Tổng tiền sản phẩm:", itemTotal); // Kết quả in ra: 100000

3.2. Ví dụ 3.2: Nâng cấp hàm tính số tiền giảm giá và thanh toán (Function Expression)
Sử dụng cú pháp Function Expression gán hàm vào một hằng số const calculateFinalPayment. Hàm tính toán tiền chiết khấu dựa trên tỷ lệ và trả về số tiền thực tế khách hàng cần thanh toán.

  

    

      
      
      
    

    
// Khai báo hàm biểu thức (Function Expression) tính số tiền thanh toán
const calculateFinalPayment = function(subtotal, discountRate) {
  const discountAmount = subtotal * discountRate;
  const finalPayment = subtotal - discountAmount;
  return finalPayment;
};

// Gọi hàm tính tiền cho hóa đơn 500.000 VNĐ với mức giảm giá 10%
const subtotal = 500000;
const discountRate = 0.1; // Giảm giá 10%
const amountToPay = calculateFinalPayment(subtotal, discountRate);

console.log("Số tiền khách phải trả:", amountToPay); // Kết quả in ra: 450000

            4. Tổng kết bài học & Các lỗi thường gặp
          


          

            
4.1. Kiến thức trọng tâm
  • Hàm giúp tái sử dụng mã nguồn, đóng gói logic tính toán và giảm thiểu nguy cơ sai sót khi lập trình.
  • Function Declaration được tự động đẩy lên đầu phạm vi (Hoisting), cho phép gọi hàm ở bất kỳ vị trí nào trong tập tin.
  • Function Expression chỉ có thể được gọi sau khi câu lệnh khai báo biến chứa hàm đã chạy thành công.
  • Từ khóa return trả về giá trị tính toán và ngay lập tức chấm dứt luồng thực thi trong thân hàm.
  • Mọi hàm không khai báo từ khóa return sẽ mặc định trả về giá trị undefined.

4.3. Các lỗi thường gặp & Cách khắc phục
Lỗi 1: Gọi Function Expression trước khi khai báo
Do nghĩ rằng Function Expression có cơ chế Hoisting giống Function Declaration, lập trình viên gọi hàm trước dòng gán biến dẫn đến chương trình bị ngắt đột ngột.
MÃ SAI (BAD CODE)

  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// Lỗi: Gọi hàm biểu thức trước khi khai báo
const total = calculateTotal(50000, 2);

const calculateTotal = function(price, quantity) {
  return price * quantity;
};


MÃ ĐÚNG (GOOD CODE)

  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// Đúng: Khai báo hàm biểu thức trước, sau đó mới gọi hàm
const calculateTotal = function(price, quantity) {
  return price * quantity;
};

const total = calculateTotal(50000, 2);
console.log("Tổng tiền:", total);


Lỗi 2: Quên lệnh return hoặc viết mã phía sau lệnh return
Nếu quên câu lệnh return, giá trị nhận được khi gọi hàm sẽ là undefined. Ngược lại, những câu lệnh nằm phía sau từ khóa return sẽ bị bỏ qua hoàn toàn và không bao giờ thực thi.
MÃ SAI (BAD CODE)

  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
function calculateDiscount(subtotal, discountRate) {
  const discount = subtotal * discountRate;
  return discount;
  // Mã chết (unreachable code): Không bao giờ chạy
  console.log("Đã tính xong chiết khấu");
}

function calculateTotalWithoutReturn(subtotal, discount) {
  const total = subtotal - discount;
  // Thiếu return -> Hàm trả về undefined
}
const result = calculateTotalWithoutReturn(100000, 10000);
console.log(result); // In ra: undefined


MÃ ĐÚNG (GOOD CODE)

  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
function calculateDiscount(subtotal, discountRate) {
  const discount = subtotal * discountRate;
  console.log("Đã tính xong chiết khấu");
  return discount; // Return đặt ở cuối khối tính toán
}

function calculateTotalWithReturn(subtotal, discount) {
  const total = subtotal - discount;
  return total; // Trả về giá trị tính toán đúng
}
const result = calculateTotalWithReturn(100000, 10000);
console.log("Kết quả:", result); // In ra: 90000
