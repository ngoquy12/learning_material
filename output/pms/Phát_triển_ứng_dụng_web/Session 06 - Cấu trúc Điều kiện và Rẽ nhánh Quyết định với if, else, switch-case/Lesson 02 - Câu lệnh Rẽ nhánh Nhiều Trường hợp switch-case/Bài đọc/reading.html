Câu lệnh Rẽ nhánh Nhiều Trường hợp switch-case

1. Tại sao cần dùng switch-case thay thế cho chuỗi câu lệnh if-else phức tạp?

Hãy tưởng tượng bạn đang xây dựng hệ thống quản lý đơn hàng cho một sàn thương mại điện tử như Shopee hoặc Tiki. Khi khách hàng truy cập vào trang chi tiết đơn hàng, ứng dụng cần hiển thị trạng thái xử lý hiện tại và đưa ra các hành động tương ứng dựa trên mã trạng thái từ máy chủ gửi về (ví dụ: PENDING, PROCESSING, SHIPPED, DELIVERED, CANCELLED).

Nếu lập trình viên sử dụng cấu trúc if ... else if ... else if để kiểm tra từng trạng thái, đoạn mã sẽ nhanh chóng trở nên cồng kềnh, lặp đi lặp lại phép so sánh bằng === với cùng một biến. Điều này làm giảm tính đọc được của mã nguồn và khiến công việc bảo trì khi bổ sung trạng thái mới gặp nhiều rủi ro.

Để giải quyết bài toán rẽ nhánh theo một giá trị cụ thể với nhiều trường hợp cố định, JavaScript cung cấp câu lệnh switch-case. Cấu trúc này giúp mã nguồn gọn gàng, rõ ràng và tối ưu hiệu năng xử lý khi định tuyến logic kinh doanh.

2. Cú pháp và cơ chế rẽ nhánh switch-case trong JavaScript

2.1. Cú pháp cơ bản của switch-case và so sánh nghiêm ngặt (Strict Comparison)

Câu lệnh switch đánh giá một biểu thức truyền vào một lần duy nhất, sau đó lần lượt so sánh giá trị của biểu thức đó với từng nhãn case theo thứ tự từ trên xuống dưới. Điều quan trọng cần lưu ý là phép so sánh giữa biểu thức và các giá trị trong case luôn sử dụng phép so sánh nghiêm ngặt (===), tức là phải khớp cả về mặt kiểu dữ liệu lẫn giá trị.

Cú pháp chuẩn câu lệnh switch-case trong JavaScript
switch (expression) {
  case value1:
    // Khối lệnh thực thi khi expression === value1
    break;
  case value2:
    // Khối lệnh thực thi khi expression === value2
    break;
  default:
    // Khối lệnh thực thi khi không khớp với bất kỳ case nào
    break;
}

 Yêu cầu bài toán:
Kiểm tra mã trạng thái đơn hàng order_status từ hệ thống để in ra thông báo giao diện tiếng Việt cho người mua.

  

    

      
      
      
    

    
// Biến chứa trạng thái đơn hàng hiện tại
const order_status = "PENDING";
let status_message = "";

// Áp dụng switch-case để kiểm tra trạng thái
switch (order_status) {
  case "PENDING":
    status_message = "Đơn hàng đang chờ thanh toán.";
    break;
  case "PROCESSING":
    status_message = "Cửa hàng đang chuẩn bị sản phẩm.";
    break;
  case "SHIPPED":
    status_message = "Đơn hàng đang trên đường giao đến bạn.";
    break;
  case "DELIVERED":
    status_message = "Đơn hàng đã được giao thành công.";
    break;
  default:
    status_message = "Trạng thái đơn hàng không hợp lệ.";
    break;
}

console.log(status_message); // Kết quả: Đơn hàng đang chờ thanh toán.

  • expression: Biểu thức hoặc biến được đưa vào kiểm tra (trong ví dụ trên là order_status).
  • case value: Nhãn chứa giá trị cần so sánh. Nếu expression === value trả về true, trình duyệt sẽ nhảy vào thi hành các câu lệnh nằm sau dấu hai chấm.
  • break; Lệnh thoát khỏi khối switch ngay lập tức sau khi đã thực thi xong các câu lệnh của case tương ứng.
2.2. Vai trò của từ khóa break và kỹ thuật gom nhóm trường hợp (Fall-through Grouping)
Nếu bạn quên không ghi từ khóa break ở cuối một khối case, chương trình JavaScript sẽ không tự động dừng lại. Thay vào đó, nó sẽ tiếp tục thi hành các câu lệnh của các case bên dưới bất kể điều kiện có khớp hay không. Hiện tượng này gọi là Fall-through (tràn lệnh).
Mặc dù Fall-through có thể gây ra lỗi logic nếu vô tình quên break, các lập trình viên thường chủ động tận dụng tính chất này để gom nhóm nhiều case xử lý chung một khối logic.
 Yêu cầu bài toán:
Gom nhóm các trạng thái xử lý kho khác nhau (PROCESSING, PACKING, READY_TO_SHIP) để hiển thị thông báo chung là "Đơn hàng đang trong quá trình chuẩn bị tại kho".

  

    

      
      
      
    

    
// Trạng thái đơn hàng chi tiết từ kho vận
const current_stage = "PACKING";
let stage_group_title = "";

switch (current_stage) {
  // Gom nhóm 3 case cùng chia sẻ chung 1 xử lý
  case "PROCESSING":
  case "PACKING":
  case "READY_TO_SHIP":
    stage_group_title = "Đơn hàng đang trong quá trình chuẩn bị tại kho.";
    break;
    
  case "SHIPPED":
  case "IN_TRANSIT":
    stage_group_title = "Đơn hàng đang được vận chuyển.";
    break;
    
  case "DELIVERED":
    stage_group_title = "Đơn hàng đã hoàn tất.";
    break;
    
  default:
    stage_group_title = "Trạng thái không xác định.";
    break;
}

console.log(stage_group_title); // Kết quả: Đơn hàng đang trong quá trình chuẩn bị tại kho.

  

  

    

      
         KẾT QUẢ THỰC THI (CONSOLE OUTPUT):
      
    

    

  


  • Chủ động gom nhóm (Intentional Fall-through): Khi đặt các thẻ case liền nhau mà không có mã lệnh và từ khóa break ở giữa, tất cả các trường hợp này sẽ thi hành chung khối mã của case cuối cùng có câu lệnh.
  • Tối ưu mã nguồn: Giúp giảm thiểu lặp lại mã (DRY - Don't Repeat Yourself) khi nhiều giá trị đầu vào dẫn đến cùng một hành xử hệ thống.
2.3. Xử lý giá trị mặc định với default và các trường hợp ngoại lệ
Nhánh default đóng vai trò tương tự khối else trong chuỗi câu lệnh điều kiện. Nhánh này sẽ tự động thi hành nếu giá trị của biểu thức kiểm tra không khớp với bất kỳ trường hợp case nào trước đó.
 Yêu cầu bài toán:
Bảo vệ hệ thống khỏi các mã trạng thái giao dịch không hợp lệ hoặc dữ liệu bất thường từ API bằng nhánh phòng ngự default.

  

    

      
      
      
    

    
// Mã trạng thái từ API bên thứ ba bị lỗi hoặc không xác định
const unknown_status = "UNKNOWN_ERROR_CODE";
let error_log = "";

switch (unknown_status) {
  case "SUCCESS":
    error_log = "Giao dịch thành công.";
    break;
  case "FAILED":
    error_log = "Giao dịch thất bại.";
    break;
  default:
    // Nhánh fallback an toàn khi gặp dữ liệu không khớp
    error_log = "Cảnh báo: Mã trạng thái không hợp lệ! Vui lòng liên hệ CSKH.";
    break;
}

console.log(error_log); // Kết quả: Cảnh báo: Mã trạng thái không hợp lệ! Vui lòng liên hệ CSKH.

  

  

    

      
         KẾT QUẢ THỰC THI (CONSOLE OUTPUT):
      
    

    

  


  • Vị trí đặt default: Nhánh default thường được đặt ở cuối cấu trúc switch để giữ cho mã nguồn mạch lạc. Dù có thể đặt ở vị trí bất kỳ, đặt ở cuối cùng là thực hành chuẩn tốt nhất.
  • Tính tùy chọn: Nhánh default không bắt buộc phải có, nhưng luôn được khuyến nghị viết vào để xử lý lỗi rủi ro dữ liệu ngoài dự kiến.

            3. Các ví dụ ứng dụng thực tiễn
          


          

            
3.1. Ví dụ 3.1: Kiểm tra trạng thái thanh toán đơn hàng (Cú pháp cơ bản)
Trong ví dụ này, chúng ta sử dụng switch-case cơ bản để chuyển đổi mã thanh toán viết tắt từ phía Server thành tên phương thức thanh toán thân thiện để hiển thị lên trên hóa đơn của người dùng.
 Yêu cầu bài toán:
Định ánh xạ mã phương thức thanh toán (COD, MOMO, CREDIT_CARD, BANK_TRANSFER) thành tên hiển thị tiếng Việt tương ứng.

  

    

      
      
      
    

    
function getPaymentMethodName(payment_code) {
  let method_name = "";
  
  switch (payment_code) {
    case "COD":
      method_name = "Thanh toán khi nhận hàng (COD)";
      break;
    case "MOMO":
      method_name = "Ví điện tử MoMo";
      break;
    case "CREDIT_CARD":
      method_name = "Thẻ tín dụng / Ghi nợ quốc tế";
      break;
    case "BANK_TRANSFER":
      method_name = "Chuyển khoản ngân hàng QR Code";
      break;
    default:
      method_name = "Phương thức thanh toán không hợp lệ";
      break;
  }
  
  return method_name;
}

// Chạy thử nghiệm
console.log(getPaymentMethodName("MOMO")); 
// Output: Ví điện tử MoMo

3.2. Ví dụ 3.2: Phân loại nhóm trạng thái vận chuyển và phí giao hàng (Gom nhóm case)
Áp dụng kỹ thuật gom nhóm case không có từ khóa break để phân vùng giao hàng thành các mức phí vận chuyển cố định.
 Yêu cầu bài toán:
Tính toán mức phí vận chuyển dựa trên mã vùng địa lý của khách hàng, các khu vực có cùng chi phí giao hàng sẽ được gom chung một nhóm xử lý.

  

    

      
      
      
    

    
function calculateShippingFeeByRegion(region_code) {
  let shipping_fee = 0;
  
  switch (region_code) {
    // Gom nhóm các khu vực nội thành (Đồng giá 15.000 VNĐ)
    case "INNER_CITY":
    case "URBAN":
      shipping_fee = 15000;
      break;
      
    // Gom nhóm các khu vực ngoại thành (Đồng giá 30.000 VNĐ)
    case "SUBURBAN":
    case "OUTER_CITY":
      shipping_fee = 30000;
      break;
      
    // Gom nhóm vùng hải đảo, miền núi xa (Đồng giá 55.000 VNĐ)
    case "REMOTE_ISLAND":
    case "MOUNTAIN":
      shipping_fee = 55000;
      break;
      
    default:
      shipping_fee = 30000; // Mức phí mặc định tiêu chuẩn
      break;
  }
  
  return shipping_fee;
}

// Chạy thử nghiệm
console.log("Phí vận chuyển ngoại thành:", calculateShippingFeeByRegion("OUTER_CITY"), "VNĐ");
// Output: Phí vận chuyển ngoại thành: 30000 VNĐ

3.3. Ví dụ 3.3: Xử lý luồng hủy đơn hàng và hoàn tiền tự động (Kịch bản doanh nghiệp)
Trong hệ thống thương mại điện tử thực tế, việc xử lý yêu cầu hủy đơn hàng phụ thuộc vào hai yếu tố: Trạng thái hiện tại của đơn hàng và Phương thức thanh toán khách đã dùng trước đó. Ví dụ này kết hợp switch-case lồng nhau (Nested switch) để đưa ra quyết định kinh doanh chuẩn xác.
 Yêu cầu bài toán:
Viết hàm xử lý yêu cầu hủy đơn hàng, tự động tính số tiền hoàn trả cho khách hàng dựa trên trạng thái giao dịch và phương thức thanh toán ban đầu.

  

    

      
      
      
    

    
function processOrderCancellation(order_details) {
  const { order_id, order_status, payment_method, order_amount } = order_details;
  let cancellation_result = {
    success: true,
    refund_amount: 0,
    message: ""
  };

  switch (order_status) {
    case "PENDING_PAYMENT":
      cancellation_result.refund_amount = 0;
      cancellation_result.message = "Đơn hàng đã được hủy thành công. Chưa phát sinh thanh toán.";
      break;

    case "PAID":
    case "PROCESSING":
      // Lồng switch để kiểm tra phương thức hoàn tiền
      switch (payment_method) {
        case "COD":
          cancellation_result.refund_amount = 0;
          cancellation_result.message = "Hủy đơn thành công. Khách hàng chưa thanh toán tiền mặt.";
          break;
        case "MOMO":
        case "BANK_TRANSFER":
        case "CREDIT_CARD":
          cancellation_result.refund_amount = order_amount;
          cancellation_result.message = `Hủy đơn thành công. Đã hoàn ${order_amount.toLocaleString('vi-VN')} VNĐ vào tài khoản.`;
          break;
        default:
          cancellation_result.success = false;
          cancellation_result.message = "Lỗi: Phương thức thanh toán không hỗ trợ hoàn tiền tự động.";
          break;
      }
      break;

    case "SHIPPED":
      cancellation_result.success = false;
      cancellation_result.message = "Không thể hủy đơn hàng đang giao. Vui lòng yêu cầu Trả hàng sau khi nhận.";
      break;

    default:
      cancellation_result.success = false;
      cancellation_result.message = "Trạng thái đơn hàng không hợp lệ để thực hiện hủy.";
      break;
  }

  return cancellation_result;
}

// Chạy thử nghiệm kịch bản hủy đơn hàng đã thanh toán qua MoMo
const sample_order = {
  order_id: "ORD99281",
  order_status: "PROCESSING",
  payment_method: "MOMO",
  order_amount: 450000
};

console.log(processOrderCancellation(sample_order));

}

            4. Tổng kết bài học & Các lỗi thường gặp
          


          

            
4.1. Kiến thức trọng tâm
  • So sánh nghiêm ngặt: Câu lệnh switch-case luôn so sánh biểu thức với các giá trị bằng phép toán === (so sánh cả kiểu dữ liệu và giá trị).
  • Ngắt lệnh với break: Luôn sử dụng từ khóa break ở cuối mỗi case trừ khi bạn chủ động muốn dùng kỹ thuật gom nhóm lệnh (Fall-through).
  • Nhánh dự phòng default: Luôn khai báo nhánh default ở cuối khối lệnh để bắt các giá trị bất thường ngoài phạm vi dự kiến.
4.2. Bảng Ma trận Quyết định (Decision Matrix Table)

Khi nào nên tránhTránh dùng khi có quá nhiều trường hợp so sánh bằng với cùng một biến (gây rối mã).Tránh dùng khi điều kiện kiểm tra là biểu thức khoảng so sánh hơn kém.Tránh dùng khi mỗi nhánh cần thực hiện một chuỗi thao tác xử lý phức tạp.


4.3. Các lỗi thường gặp & Lưu ý thực tế
 Lỗi 1: Tràn lệnh ngoài ý muốn do quên từ khóa break (Accidental Fall-through)
Đây là lỗi phổ biến nhất khiến chương trình thực thi tràn sang cả các case bên dưới gây sai lệch logic kết quả.

  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// Quên break ở case "PENDING"
switch (status) {
  case "PENDING":
    msg = "Chờ thanh toán";
    // Thiếu break!
  case "SHIPPED":
    msg = "Đang giao hàng";
    break;
}
// msg sẽ bị ghi đè thành "Đang giao hàng"!



  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// Luôn có break ngắt khối lệnh
switch (status) {
  case "PENDING":
    msg = "Chờ thanh toán";
    break;
  case "SHIPPED":
    msg = "Đang giao hàng";
    break;
}


 Lỗi 2: Trùng lặp phạm vi biến (Lexical Scope Issue) trong các nhánh case
Tất cả các case trong cùng một câu lệnh switch chia sẻ chung một phạm vi biến (scope). Việc khai báo cùng tên biến bằng let hoặc const ở nhiều case sẽ gây ra lỗi SyntaxError.

  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
switch (action) {
  case "CREATE":
    const message = "Tạo mới"; // Khai báo message
    break;
  case "UPDATE":
    const message = "Cập nhật"; // Lỗi: Identifier 'message' has already been declared!
    break;
}



  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
switch (action) {
  case "CREATE": {
    const message = "Tạo mới"; // Sử dụng cặp ngoặc {} để tạo khối scope riêng
    break;
  }
  case "UPDATE": {
    const message = "Cập nhật"; // Hợp lệ!
    break;
  }
}
