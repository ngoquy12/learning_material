1. Tại sao cần Cấu trúc Rẽ nhánh trong Xử lý Thanh toán Đơn hàng?

Hãy tưởng tượng bạn đang xây dựng tính năng tính toán hóa đơn thanh toán cho một ứng dụng thương mại điện tử như Shopee hoặc Tiki. Hệ thống cần tự động tính số tiền cuối cùng khách hàng phải trả dựa trên giá trị đơn hàng, phí giao hàng và chính sách ưu đãi thành viên.

Nếu mã nguồn chỉ thực thi tuyến tính từng dòng từ trên xuống dưới mà không có khả năng kiểm tra điều kiện, mọi đơn hàng sẽ bị áp chung một mức phí giao hàng cố định 30.000 VNĐ. Điều này dẫn đến vấn đề nghiêm trọng: những khách hàng mua đơn hàng lớn trị giá 1.500.000 VNĐ sẽ cảm thấy thất vọng vì không được miễn phí giao hàng như cam kết. Ngược lại, nếu hệ thống miễn phí giao hàng cho tất cả mọi người, những đơn hàng nhỏ 20.000 VNĐ sẽ khiến doanh nghiệp bị lỗ nặng chi phí vận chuyển.

Làm sao để máy tính có thể tự động kiểm tra giá trị từng đơn hàng và đưa ra quyết định tính toán chính xác cho từng trường hợp? Đó là lý do chúng ta cần đến cấu trúc rẽ nhánh với các câu lệnh if, else if và else trong JavaScript.

2. Cú pháp và Cơ chế Hoạt động của Câu lệnh Điều kiện if, if-else trong JavaScript

2.1. Cấu trúc câu lệnh if đơn và Giá trị Boolean (Single if & Boolean Evaluation)

Trong JavaScript, câu lệnh if là hình thức kiểm tra điều kiện cơ bản nhất. Khối lệnh bên trong câu lệnh if chỉ được thực thi khi biểu thức điều kiện trả về giá trị true (Đúng). Nếu biểu thức điều kiện trả về giá trị false (Sai), JavaScript sẽ bỏ qua toàn bộ khối lệnh đó và tiếp tục thực thi các dòng mã bên dưới.

if (condition) {
  // Khối lệnh thực thi khi condition trả về giá trị true
}
KẾT QUẢ THỰC THI (CONSOLE OUTPUT): 

  


  • condition: Biểu thức logic được đặt trong cặp dấu ngoặc đơn (). Biểu thức này tự động được đánh giá về kiểu dữ liệu Boolean (true hoặc false) sử dụng các toán tử so sánh như >, >=, <, <=, ===, !==.
  • { ... } (Khối lệnh): Cặp dấu ngoặc nhọn bao bọc các câu lệnh sẽ được thi hành khi điều kiện thỏa mãn. Dù khối lệnh chỉ có một dòng mã, việc luôn sử dụng cặp dấu ngoặc nhọn là quy chuẩn bắt buộc trong lập trình doanh nghiệp nhằm tránh các lỗi logic tiềm ẩn.

            3. Các ví dụ ứng dụng thực tiễn
          


          

            
3.1. Ví dụ cú pháp cơ bản: Kiểm tra giá trị đơn hàng tối thiểu áp dụng Mã Giảm Giá
Ví dụ cơ bản minh họa việc áp dụng câu lệnh if đơn để kiểm tra giá trị đơn hàng tối thiểu trước khi kích hoạt mã giảm giá.
 Yêu cầu bài toán:
Khách hàng áp dụng mã voucher giảm 50.000 VNĐ. Điều kiện sử dụng là đơn hàng phải đạt từ 300.000 VNĐ trở lên.

  

    

      
      
      
    

    
let orderTotal = 350000;
let voucherDiscount = 0;

// Kiểm tra xem giá trị đơn hàng có đạt ngưỡng tối thiểu 300.000 VNĐ hay không
if (orderTotal >= 300000) {
  voucherDiscount = 50000;
  console.log("Mã giảm giá áp dụng thành công! Được giảm 50.000 VNĐ.");
}

let finalAmount = orderTotal - voucherDiscount;
console.log("Số tiền thanh toán cuối cùng:", finalAmount, "VNĐ");

3.2. Ví dụ logic nghiệp vụ: Tính toán phí giao hàng theo giá trị đơn hàng và hạng thành viên VIP
Ví dụ thực tế minh họa cách phối hợp câu lệnh if-else cùng toán tử logic OR (||) để tính phí vận chuyển cho nhiều trường hợp ưu đãi khác nhau.
 Yêu cầu bài toán:
Miễn phí giao hàng (0 VNĐ) nếu khách hàng là tài khoản VIP hoặc giá trị đơn hàng đạt từ 500.000 VNĐ trở lên. Nếu không đáp ứng cả hai điều kiện, thu phí giao hàng 30.000 VNĐ.

  

    

      
      
      
    

    
let orderTotal = 400000;
let isVipUser = false;
let shippingFee = 0;

// Đánh giá điều kiện kết hợp sử dụng toán tử logic OR (||)
if (isVipUser === true || orderTotal >= 500000) {
  shippingFee = 0;
  console.log("Bạn thỏa mãn điều kiện Miễn phí giao hàng!");
} else {
  shippingFee = 30000;
  console.log("Không đủ điều kiện Freeship. Áp dụng phí giao hàng 30.000 VNĐ.");
}

console.log("Phí giao hàng được ghi nhận:", shippingFee, "VNĐ");

3.3. Ví dụ kịch bản doanh nghiệp: Hệ thống tính Tổng thanh toán hoàn chỉnh (Checkout Processing Engine)
Kịch bản doanh nghiệp hoàn chỉnh tích hợp toàn bộ các quy tắc rẽ nhánh để tính toán số tiền giảm giá, phí giao hàng và tổng tiền cần thanh toán cho đơn hàng thương mại điện tử.
 Yêu cầu bài toán:
Xây dựng luồng xử lý Checkout hoàn chỉnh cho đơn hàng 1.200.000 VNĐ của thành viên VIP có mã FREESHIP. Tính toán chính xác giảm giá theo bậc, ưu đãi vận chuyển và in ra hóa đơn tổng hợp.

  

    

      
      
      
    

    
// Hệ thống tính toán Tổng thanh toán Đơn hàng (E-Commerce Checkout Engine)
let orderTotal = 1200000;
let isVipUser = true;
let voucherCode = "FREESHIP";

let discountRate = 0;
let shippingFee = 30000;

// 1. Kiểm tra chính sách giảm giá theo giá trị đơn hàng
if (orderTotal >= 1000000) {
  discountRate = 0.15; // Giảm 15% cho đơn từ 1 triệu
} else if (orderTotal >= 500000) {
  discountRate = 0.10; // Giảm 10% cho đơn từ 500k
} else {
  discountRate = 0;
}

// 2. Kiểm tra ưu đãi phí giao hàng cho VIP hoặc mã FREESHIP
if (isVipUser === true || voucherCode === "FREESHIP") {
  shippingFee = 0;
  console.log("Áp dụng miễn phí giao hàng do khách hàng VIP hoặc nhập mã FREESHIP!");
} else {
  shippingFee = 30000;
}

// 3. Tính toán số tiền giảm và Tổng thanh toán cuối cùng
let discountAmount = orderTotal * discountRate;
let finalPayment = orderTotal - discountAmount + shippingFee;

console.log("Giá trị đơn hàng ban đầu:", orderTotal, "VNĐ");
console.log("Số tiền được giảm giá:", discountAmount, "VNĐ");
console.log("Phí giao hàng:", shippingFee, "VNĐ");
console.log("Tổng tiền khách thanh toán:", finalPayment, "VNĐ");

4. Tổng kết bài học & Các lỗi thường gặp
4.1. Kiến thức trọng tâm
  • Kiểu dữ liệu Boolean: Biểu thức điều kiện trong câu lệnh rẽ nhánh bắt buộc phải đánh giá về giá trị luận lý true hoặc false.
  • Cấu trúc if đơn: Chỉ thực thi khối lệnh khi điều kiện đạt giá trị true.
  • Cấu trúc if-else: Chia luồng xử lý thành hai nhánh độc lập tuyệt đối; luôn có duy nhất một nhánh được chọn để chạy.
  • Chuỗi if - else if - else: Đánh giá lần lượt từng điều kiện từ trên xuống dưới và sẽ dừng ngay khi gặp điều kiện đầu tiên trả về true.
4.2. Bảng Ma trận Quyết định (Decision Matrix Table)


Cấu trúc điều kiệnKhi nào nên sử dụngKhi nào nên tránhVí dụ thực tế
if đơnKhi chỉ cần thực hiện hành động bổ sung khi thỏa mãn điều kiện, không cần xử lý nhánh ngược lại.Tránh dùng khi cần xử lý hai kịch bản đối lập hoàn toàn.Cộng điểm thưởng khi đơn hàng vượt mốc.
if-elseKhi có đúng 2 trường hợp loại trừ lẫn nhau (Ví dụ: Đúng/Sai, VIP/Thường, Bật/Tắt).Tránh lồng nhiều lớp if-else liên tiếp gây phức tạp mã nguồn (Phân nhánh quá sâu).Kiểm tra trạng thái tài khoản VIP để tính phí ship.
if - else if - elseKhi cần phân loại xử lý theo nhiều bậc hoặc nhiều khoảng giá trị khác nhau.Tránh dùng khi có quá nhiều giá trị đơn lẻ cố định (Nên xem xét dùng switch-case).Tính tỷ lệ giảm giá theo từng bậc giá trị đơn hàng.


4.3. Các lỗi thường gặp & Lưu ý thực tế
 Lỗi 1: Nhầm lẫn giữa toán tử gán (=) và toán tử so sánh bằng (===)
Việc sử dụng một dấu bằng = trong điều kiện sẽ thực hiện phép gán giá trị thay vì phép so sánh. Phép gán trả về chính giá trị được gán, khiến điều kiện luôn luôn trả về truthy và khối lệnh luôn thi hành ngoài ý muốn.

  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// LỖI: isVipUser bị gán lại thành true!
if (isVipUser = true) {
  shippingFee = 0;
}



  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// Đúng: So sánh giá trị bằng toán tử ===
if (isVipUser === true) {
  shippingFee = 0;
}


 Lỗi 2: Sai thứ tự điều kiện trong chuỗi if - else if - else
Đặt điều kiện có phạm vi rộng (tổng quát) trước điều kiện cụ thể hơn sẽ làm cho các nhánh phía sau bị ẩn và không bao giờ được chạm tới.

  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// Đơn 2 triệu sẽ bị khớp ngay nhánh 500k!
if (orderTotal >= 500000) {
  discountRate = 0.05;
} else if (orderTotal >= 1500000) {
  discountRate = 0.20; // Không bao giờ chạy
}



  

    
      
      
      
      Cú pháp mẫu Javascript
    
    
  

  
// Đúng: Sắp xếp điều kiện từ cao xuống thấp
if (orderTotal >= 1500000) {
  discountRate = 0.20;
} else if (orderTotal >= 500000) {
  discountRate = 0.05;
}
