Người dùng chốt: môn NodeJS, 2 session, mục tiêu **viết API với Express**, tối đa 7 lesson, **MySQL** làm cơ sở dữ liệu. ### Hàm lỗi và định dạng phản hồi
- `httpError(status, code, message, details)` trả `Error` có thuộc tính `status`, `code`, `details` (tùy chọn). Dùng: `throw httpError(404, "NOT_FOUND", "Không tìm thấy sản phẩm")`, hoặc `next(httpError(...))`.
- Phản hồi thành công: một tài nguyên → trả đối tượng; danh sách KHÔNG phân trang (Lesson 1-4) → mảng; danh sách phân trang (từ Lesson 5) → `{ data: [...], meta: { page, limit, total, totalPages } }`; `POST` tạo mới → 201 + đối tượng vừa tạo (có `id`); `DELETE` → 204 không thân; `PUT`/`PATCH` → 200 + đối tượng sau khi sửa.
- Phản hồi lỗi (từ Lesson 2 trở đi): `{ error: { code, message, details? } }`. Mã lỗi: `VALIDATION_ERROR` (400, `details` là mảng `{ field, message }`), `UNAUTHORIZED` (401), `FORBIDDEN` (403), `NOT_FOUND` (404), `CONFLICT` (409), `RATE_LIMITED` (429), `INTERNAL_ERROR` (500; message cố định "Lỗi máy chủ", không lộ chi tiết). Route không tồn tại: 404 `NOT_FOUND` "Không tìm thấy đường dẫn". JSON sai cú pháp: 400 `VALIDATION_ERROR` "JSON không hợp lệ".
- Thông báo tiếng Việt có dấu, cố định (test khớp): "Không tìm thấy sản phẩm", "Dữ liệu không hợp lệ", "Danh mục không tồn tại", "Sản phẩm đã có trong đơn hàng, không thể xóa", "Email đã được đăng ký", "Email hoặc mật khẩu không đúng", "Thiếu hoặc sai mã xác thực", "Bạn không có quyền thực hiện thao tác này", "Không đủ hàng trong kho", "Không tìm thấy đơn hàng", "Lỗi máy chủ", "Quá nhiều yêu cầu, hãy thử lại sau".
### Dữ liệu API và JSON
- JSON dùng `camelCase` (chuyển từ cột `snake_case` bằng `AS`): sản phẩm `{ id, name, price, stock, categoryId, categoryName }` (có `JOIN categories`); người dùng công khai `{ id, email, fullName, role }` (KHÔNG BAO GIỜ trả `passwordHash`); đơn hàng `{ id, userId, status, total, createdAt, items: [{ productId, name, quantity, unitPrice }] }`.
- Tiền VND là số nguyên (bội số của 1.000); hàm hiển thị nếu cần là `formatVnd` viết tay (không dùng trong API trả số).
- Xác thực: `Authorization: Bearer <token>`; JWT payload `{ sub: <id người dùng>, role }`; `req.user = { id, role }`; đăng nhập trả `{ token, user }` (200); đăng ký trả người dùng công khai (201).
- Tài khoản mẫu (mật khẩu `Matkhau123`): Rikkei Shop: `admin@rikkei.shop` (admin, id 1), `lan@rikkei.shop` (customer, id 2), `hung@rikkei.shop` (customer, id 3); Rikkei Learn: `admin@rikkei.edu` (admin, id 1), `an@rikkei.edu`, `binh@rikkei.edu`, `chi@rikkei.edu`, `dung@rikkei.edu`, `giang@rikkei.edu` (student, id 2-6).

## Mô phỏng tương tác trong bài đọc HTML (`l1_` đến `l7_`)
Khối "Mô phỏng tương tác" cuối Mục 3 phải TRỰC QUAN và chạy thật bằng JavaScript thuần trong trang (không cần máy chủ thật; các bảng kết quả SQL/JWT/phản hồi được TÍNH TRƯỚC bằng cách chạy thật rồi nhúng dữ liệu vào trang). Riêng: L1 vòng đời một yêu cầu qua event loop (nhiều yêu cầu đến, tác vụ I/O chạy nền, callback quay lại; chuyển chế độ "chặn" vs "không chặn" xem thời gian phục vụ) + bảng "HTTP trong 1 phút"; L2 đường ống middleware: người dùng kéo thứ tự 4-5 middleware (logger, express.json, requireApiKey, route, 404/lỗi), chọn một yêu cầu mẫu và xem nó đi qua từng bước, dừng ở đâu, trả mã nào; L3 sân chơi SQL: chọn câu truy vấn mẫu từ danh sách (SELECT/WHERE/JOIN/GROUP BY) trên bảng Rikkei Shop, hiện bảng kết quả (dữ liệu tính trước từ MySQL thật) và tô sáng hàng được chọn; L4 hồ kết nối: pool 3 kết nối, bấm gửi nhiều truy vấn xem kết nối bận/rảnh và hàng đợi; ô nhập tìm kiếm cho thấy SQL cuối cùng khi nối chuỗi so với dùng `?` (chuỗi `' OR 1=1 --`); L5 yêu cầu đi qua các tầng route → validate → controller → repository với bảng mã lỗi: nhập body mẫu (hợp lệ/thiếu trường/giá âm/danh mục không tồn tại) xem nó dừng ở tầng nào và phản hồi ra sao; L6 bộ giải mã JWT (dán/chọn token mẫu, hiển thị header/payload/signature, đổi payload thì chữ ký hết khớp; mô phỏng hết hạn) + sơ đồ luồng đăng nhập → token → gọi route bảo vệ với kết quả 401/403/200 theo vai trò; L7 bảng kiểm thử: chọn một test Supertest mẫu và xem yêu cầu/phản hồi, bật/tắt CORS xem trình duyệt chặn thế nào, bộ đếm giới hạn tần suất (bấm gửi nhiều yêu cầu thấy 429).
