| Bài | Cấp | Lesson | Nội dung gợi ý |
|---|---|---|---|
| 1 | Cơ bản 1 | L1-L2 | Xây API sản phẩm TRONG BỘ NHỚ (mảng canon 5 sản phẩm): `GET /health`, `GET /products` (lọc `?category=`), `GET /products/:id` (404 JSON lỗi), `POST /products` (201, kiểm tra tối thiểu), `app.js` xuất app không listen; `server.js` có sẵn |
| 2 | Cơ bản 2 | L2 | Middleware và Router: `logger` (ghi dòng vào mảng/hàm tiêm vào), `requireApiKey` (header `x-api-key`, 401), tách Router `products`, `notFound`, `errorHandler` (định dạng lỗi chuẩn), `asyncHandler`, thứ tự middleware |
| 3 | Nâng cao 1 | L3 | Viết truy vấn SQL trên db-shop: danh sách sản phẩm kèm tên danh mục (JOIN), lọc/sắp xếp, đếm và tổng theo danh mục (GROUP BY/HAVING), top đơn hàng, sản phẩm chưa từng bán (LEFT JOIN + IS NULL)...; 8-10 truy vấn xuất từ `src/sql/queries.js`, test so kết quả |
| 4 | Nâng cao 2 | L4 | Repository mysql2: `products.repository.js` (findAll, findById, create, update, remove có tham số hóa, ánh xạ camelCase) và `orders.repository.js` `createOrder(userId, items)` bằng GIAO DỊCH (trừ kho, tạo orders + order_items, rollback nếu thiếu hàng), test cả truy vấn chống SQL injection; chưa cần HTTP đầy đủ (có thể kèm vài route) |
| 5 | Tổng hợp | L5 | API `/products` CRUD đầy đủ trên MySQL: zod, phân trang/lọc/sắp xếp (danh sách trắng), 404/409/400, định dạng phản hồi và lỗi tập trung |
| 6 | Sáng tạo | L6-L7 | Xác thực + phân quyền: register/login/me (bcryptjs, JWT), `authenticate`, `authorize("admin")` cho ghi sản phẩm, `POST /orders` (customer, dùng giao dịch Bài 4), `GET /orders` (chủ sở hữu hoặc admin), `PATCH /orders/:id/status` (admin); thêm helmet/CORS/rate limit ở mức đề khung; phần mở rộng tự do chấm Bonus |
